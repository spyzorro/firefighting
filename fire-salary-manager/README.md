# إدارة الطفايات والمرتبات

تطبيق Android عربي لتسجيل:

- الموظفين والمرتبات والسلف داخل الشهر.
- العملاء وأرقامهم واللوكيشن وعدد الطفايات والسعر.
- اسم المكان/الفرع بجانب اللوكيشن في بيانات العميل.
- نوع الطفاية ووزنها وعددها، مع تنبيه بعد 5 شهور ونصف لقرب انتهاء استيكر الطفاية.
- تقرير شهري بعدد الطفايات وإجمالي المبلغ ونسبة 25%.
- شهادات السلامة بتذكير سنوي قبل التاريخ بأسبوعين.
- التقارير الفنية بتذكير سنوي.
- عقود الصيانة بتذكير زيارة كل 3 شهور لمدة 5 سنوات، والتنبيه قبل الزيارة بـ 5 أيام، مع ترحيل الموعد لو وقع الجمعة أو السبت.
- تسجيل دخول Google ومزامنة Firebase Firestore.
- مزامنة فريق العمل بكود مشترك: كل فرد يسجل بحساب Google ويكتب نفس كود الفريق، وبعدها تقدر ترفع بياناتك للفريق أو تسترجع بيانات أعضاء الفريق عندك.
- من إجراء سريع لأي عميل يمكن تحويل العميل لفريق بكود محدد، والفريق يستلم التكليفات المفتوحة من شاشة مزامنة Google.
- عند الفني يظهر زر إنهاء وإرسال للمشرف للعميل المحول، وبعد الإرسال يختفي العميل من جهاز الفني المحلي، وتصل نسخة التحديث للمشرف لاستلامها من شاشة المزامنة.
- واجهة الفني مقفولة على التكليفات فقط: لا تظهر له لوحة تحكم المشرف، ولا يظهر في قائمة العملاء إلا العملاء المحولون له، ولا يستطيع تسجيل عميل جديد من صفحة التسجيل السريع.
- الفني يستلم التكليفات تلقائيا عند فتح التطبيق إذا كان كود الفريق محفوظا، ويضغط تسليم للمشرف فقط عند الانتهاء.
- صور الاستضافة يتم ختمها بتاريخ ووقت الرفع داخل `upload.php` قبل حفظها.
- صور الفني والمرفقات تظهر كمعاينة مباشرة تحت صفحة العميل، مع أزرار ملونة للواتساب واللوكيشن والتعديل والتسليم.
- تكليفات الفنيين تتحدث لحظيا أثناء تشغيل التطبيق، ومع وصول تكليف جديد يظهر إشعار محلي للفني.
- إضافة صور العميل عند الفني تتيح اختيار الكاميرا أو المعرض، وتظهر الصور مباشرة مع إمكانية حذف الصورة الغلط.
- صفحة المشرف `استلام من الفنيين` تعرض التحديثات المنتهية قبل اعتمادها، وتوضح تغييرات العدد والمبلغ والوزن والنوع وصور الفني.
- ألوان حالات الطفايات: استلام أزرق، تسليم جزئي رصاصي، تسليم أخضر، جاري الصيانة أصفر.
- عند رفض تحديث الفني يرجع التكليف للفني مفتوحا على آخر بيانات أرسلها حتى يعدلها ويرسلها مرة أخرى.
- تم نقل `استلام من الفنيين` إلى تبويب مستقل في الشريط العلوي، وإيقاف التحميل التلقائي والصور الثقيلة داخل الصفحة لمنع إغلاق التطبيق.
- عند إضافة صور العميل يتم تحديد `قبل التنفيذ` أو `بعد التنفيذ`، وتظهر المرحلة داخل صفحة العميل.
- من صفحة `استلام من الفنيين` يمكن مشاركة تقرير التنفيذ للجروب على واتساب مع تفاصيل الشغل وروابط صور قبل/بعد التنفيذ.
- اعتماد تحديث الفني يستبدل بيانات نفس التكليف بدل ما يكرر العميل، ورفض التحديث يخفيه من المشرف ويرجعه للفني مفتوحا للتعديل.
- تم تكبير أزرار الصفحات العلوية وتوضيح الخط عند المشرف والفنيين.
- المشرف يمكنه حذف عميل نهائيا من صفحة العميل، مع حذف بياناته المحلية وسجلات التكليف المرتبطة بنفس العميل عند توفر كود الفريق.
- التحديث الإجباري للفنيين: المشرف ينشر رقم النسخة الحالية على Firestore، والفني لو نسخته أقدم يظهر له تنبيه تحميل التحديث من `https://smmnoon.com/fire/fire-salary-manager.apk`.
- لتفادي خطأ 404 في التحديث، بعد كل Build من GitHub ارفع ملف APK الناتج إلى الاستضافة بهذا الاسم بالضبط: `/fire/fire-salary-manager.apk`.
- ممكن تخلي GitHub يرفع ملف التحديث تلقائيا بإضافة Secrets: `FTP_UPLOAD_URL` و`FTP_USERNAME` و`FTP_PASSWORD`. قيمة `FTP_UPLOAD_URL` تكون رابط FTP كامل ينتهي بـ `fire-salary-manager.apk` مثل مسار مجلد `/fire/` على الاستضافة.
- GitHub Actions يولد أيضا ملف `version.json` ويرفعه بجانب ملف APK. التطبيق يفحص `https://smmnoon.com/fire/version.json` لكل المستخدمين، ولو وجد نسخة أعلى يعرض زر تحميل مباشر. لو مسار `version.json` مختلف أضف Secret اختياري باسم `FTP_VERSION_URL`.
- مؤشر واضح أعلى التطبيق لحالة المزامنة: `متزامن مع Google` أو `في انتظار مزامنة Google`.
- إدخال صوتي في كل الخانات عن طريق زر `صوت` بجانب كل حقل.
- إدخال الصوت أصبح تشغيل/إيقاف: اضغط زر الصوت، اتكلم براحتك، ثم اضغط نفس الزر مرة ثانية لتوزيع الكلام على الخانات.
- في التسجيل السريع يوجد مربع مراجعة للصوت: سجل الكلام أولا، راجعه وعدله لو محتاج، ثم اضغط `وزع النص على الخانات`.
- إدخال صوتي جماعي: اضغط زر `قول كل البيانات مرة واحدة` وقل مثلا:
  `اسم العميل أحمد، اللوكيشن المعادي، نوع الطفاية بودرة، الوزن 6 كيلو، عدد الطفايات خمسة، السعر ألف وخمسمية`
  أو قلها بالترتيب فقط مفصولة بفواصل.
- صفحة تسجيل سريع للعميل والطفايات بدون قائمة سجلات تحت الفورم، عشان التسجيل اليومي يكون أسرع.
- نوع الطفاية والوزن لهم اختيارات سريعة، مع بقاء الكتابة والصوت متاحين.
- أوزان الطفايات السريعة تشمل فقط: `6kg`، `10kg`، `12kg`، `25kg`، `50kg`.
- قبل الحفظ يمكن عرض مربع مراجعة يلخص العميل والعدد والنوع والوزن والسعر والمدفوع والمتبقي والحالة.
- عند إدخال رقم عميل موجود، يظهر تنبيه لتأكيد إضافة العملية على نفس العميل بدل التكرار.
- شريط التنقل الأساسي أصبح مختصرا: تسجيل، العملاء، تنبيهات، التقرير، المهام، المزيد.
- صفحة `المزيد` تجمع المرتبات، الشهادات، الصيانة، الإعدادات، ومزامنة Google.
- في شاشة الطفايات يمكن قول الجملة الطبيعية مباشرة مثل:
  `محمد 20 طفاية بودرة co2 120 ريال`
  وسيتم توزيعها على اسم العميل والعدد والنوع والسعر تلقائيا.
- خانة اللوكيشن تقبل كتابة لينك Google Maps يدويا، أو زر `موقعي` لحفظ لينك موقعك الحالي.
- فتح اللوكيشن يستخدم Google Maps مباشرة عند توفره، مع إصلاح روابط الإحداثيات المحفوظة من زر `موقعي`.
- قائمة العملاء تعرض ملخص العميل فقط، وزر `فتح ملف العميل` يفتح صفحة تفاصيل مرتبة.
- أي تعديل يفتح صفحة مستقلة: تعديل بيانات العميل، تغيير حالة العميل، وتعديل بيانات الطفايات.
- بحث سريع في العملاء باسم العميل أو رقم الموبايل.
- قائمة مهام مستقلة لتسجيل ومتابعة المهام اليومية.
- فلترة العملاء حسب الحالة من شاشة العملاء.
- حالات العميل المختصرة تشمل: `جديد`، `استلام الطفايات`، `تسليم الطفايات`، `تسليم جزئي`، `جاري الصيانة`، `انتظار التحصيل`.
- يمكن تحديد حالة العميل أثناء تسجيل الطفايات، وتعديلها لاحقا من صفحة العميل.
- الحالة المختارة تظهر بلون مختلف وواضح في التسجيل السريع وصفحة تغيير الحالة.
- قائمة العملاء تعرض زر `إجراء سريع` بدل أزرار كثيرة، ومنه تفتح الملف أو واتساب أو الموقع أو التعديل أو تغيير الحالة أو مشاركة التقرير.
- زر مشاركة تقرير العميل واتساب كملخص من صفحة العميل.
- إضافة صور أو ملفات PDF كمرفقات لكل عميل، وفتحها من صفحة العميل.
- في الطفايات يمكن رفع أكثر من صورة من المعرض أو تصوير أكثر من صورة بالكاميرا، وتحديد هل العميل استلم الطفايات تاني أم لا.
- صور الطفايات تظهر كمعرض بسيط داخل ملف العميل، ويمكن فتحها أو حذفها، ومن صفحة تعديل الطفايات يمكن إضافة صور جديدة.
- عند المزامنة، الصور والمرفقات المحلية تترفع على استضافة `smmnoon.com/fire/upload.php` أولا، ثم تتسجل روابطها السحابية داخل Firestore عشان تظهر على أجهزة الفريق بدون Firebase Storage.
- تسجيل المدفوع مع عملية الطفايات، وحساب المتبقي تلقائيا في السجلات والتقرير.
- عند حفظ أي تعديل يتم إغلاق صفحة التعديل والرجوع لصفحة العميل أو القائمة بدون تداخل البيانات.
- زر واتساب لكل عميل يفتح محادثة العميل برسالة جاهزة باللهجة السعودي لتذكير الصيانة وقرب انتهاء شهادة/استيكر الطفاية.
- رسائل واتساب تذكر عدد الطفايات المسجل فعليا للعميل، وتدعم `{name}` لاسم العميل و `{count}` لعدد الطفايات. لو العدد غير موجود تتركه فارغا.
- إعدادات رسائل واتساب: اختيار أكثر من قالب، وإضافة رسالة جديدة.
- إعداد اختياري لحفظ العميل كجهة اتصال على الموبايل باسم `اسم العميل - عميل طفايات` لو الاسم والرقم موجودين والرقم غير محفوظ مسبقا.
- نسخة احتياطية محلية تلقائية على الموبايل بعد كل حفظ، مع نسخة يومية والاحتفاظ بآخر 10 أيام.
- من الإعدادات يمكن عمل نسخة احتياطية الآن أو استرجاع آخر نسخة محلية.
- صفحة `تنبيهات قريبة` تعرض تنبيهات الطفايات وشهادات السلامة وعقود الصيانة المتأخرة أو القادمة خلال 30 يوم.
- تصدير تقرير الشهر الحالي كملف PDF من صفحة تقرير الشهر.
- تصدير تقرير الشهر الحالي كملف Excel `.xls` من صفحة تقرير الشهر، شامل الملخص والطفايات والشهادات والتقارير والصيانة والسلف.
- رقم الموبايل كتابة عادية بدون إدخال صوتي.
- تعديل بيانات العملاء بعد التسجيل، وتعديل عمليات الطفايات لو حصل إدخال غلط.
- إعدادات نسب مستقلة للطفايات وشهادات السلامة والتقارير الفنية.
- الصفحة الرئيسية أبسط وأسرع، فيها زر مباشر لتسجيل عميل وطفايات بسرعة.
- فلترة حالات العملاء أصبحت أزرار أفقية صغيرة بدلا من قائمة طويلة.
- قوائم آخر عمليات الطفايات لا تظهر أثناء التسجيل، وتفتح بزر منفصل عند الحاجة.
- خانات الإدخال أكبر وأوضح في القراءة والضغط.
- أيقونات جديدة لكل تبويب في شريط التنقل.
- كل المبالغ تظهر بالريال السعودي.
- GitHub Actions يستخدم مفتاح توقيع ثابت داخل المشروع حتى تقبل نسخ APK التالية التحديث فوق بعضها.

## البناء على GitHub

1. ارفع محتويات هذا المجلد إلى Repository جديد، وليس المجلد نفسه.
   يجب أن تظهر الملفات `settings.gradle` و `build.gradle` و `.github` في الصفحة الرئيسية للريبو مباشرة.
2. من تبويب Actions شغل Workflow باسم `Build single APK`.
3. بعد انتهاء التشغيل حمل Artifact باسم `fire-salary-manager-single-apk`.
4. بداخله ستجد ملف واحد: `fire-salary-manager.apk`.

لو ظهر خطأ `does not contain a Gradle build` فهذا معناه أن الملفات مرفوعة داخل فولدر داخلي. انقل محتويات الفولدر إلى جذر الريبو أو استخدم ملف ZIP المجهز بحيث تكون الملفات في أول مستوى.

لو ظهر خطأ فيه `com.mohamed.expenseguard` فهذا معناه أن ملفات قديمة متبقية في GitHub. النسخة الحالية تنظف هذا المسار تلقائيا في GitHub Actions وتستبعده من البناء.

لو APK قديم لا يقبل التحديث فوقه، فالسبب غالبا أن النسخة القديمة كانت موقعة بمفتاح مختلف. هذه النسخة تستخدم ملف توقيع ثابت `app/firemanager-update.jks` و`versionCode` يزيد تلقائيا مع كل تشغيل GitHub Actions، لذلك النسخ التي ستخرج من هذه الملفات بعد الآن ستتحدث فوق بعضها. لو النسخة الموجودة على الموبايل موقعة بمفتاح قديم مختلف، أندرويد لن يسمح بتحديثها بنفس البيانات؛ قد تحتاج حذفها مرة واحدة فقط، وبعدها التحديثات القادمة ستثبت كتحديث طبيعي.

## ملاحظة Google Sync

تم فصل التطبيق بالكامل عن مصروفاتي. هوية التطبيق الحالية:

`com.safetyoffice.firemanager`

لكي تعمل مزامنة جوجل بدون خلط مع مصروفاتي:

1. أنشئ Firebase Project جديد مستقل لهذا التطبيق.
2. أضف Android app جديد بالـ package name:
   `com.safetyoffice.firemanager`
3. شغل GitHub Actions مرة وخد SHA-1 و SHA-256 من خطوة `Print app signing SHA fingerprints for Firebase`.
4. أضف SHA-1 و SHA-256 داخل Firebase لنفس Android app.
5. حمل ملف `google-services.json` الجديد من Firebase بعد إضافة البصمات.
6. في GitHub افتح Settings ثم Secrets and variables ثم Actions.
7. أضف أو حدّث Secret باسم:
   `GOOGLE_SERVICES_JSON`
8. ضع محتوى ملف `google-services.json` كاملا داخل هذا السر.
9. فعّل Firestore Database من Firebase.
10. في Firebase Firestore Rules استخدم قواعد مناسبة للتطبيق. يوجد ملف جاهز كبداية باسم `firebase-firestore.rules`.

الـ Workflow يرفض أي ملف Firebase يحتوي على `masrofaty` حتى لا تختلط بيانات التطبيقين.

## ملاحظة مزامنة الفريق

من شاشة `مزامنة Google` اكتب كود فريق واحد عندك وعند أفراد الفريق. بعد تسجيل الدخول بحساب Google، استخدم:

- `رفع بياناتي للفريق`: يرفع نسخة بيانات الجهاز للفريق.
- `استرجاع بيانات الفريق`: يظهر للمشرف فقط لاسترجاع بيانات أعضاء الفريق المسجلين بنفس الكود.
- `استلام التكليفات المرسلة للكود`: يظهر للفني لاستلام العملاء المحولين له فقط.

البيانات النصية والسجلات تتم عبر Firebase Firestore. الصور والمرفقات تترفع على ملف الاستضافة:

`https://smmnoon.com/fire/upload.php`

ثم يتم حفظ رابط الصورة داخل Firestore. لذلك لا تحتاج Firebase Storage ولا Blaze لخطة الصور.

## إعدادات الفريق على الاستضافة

يوجد ملف `team-config.json` يمكن رفعه على الاستضافة بجانب `upload.php` وتعديله لاحقا لإضافة أكثر من مشرف أو أنواع التركيبات/الأدريسبول.

ملاحظة: نسخة التكليفات الحالية تدعم تحويل العميل واستلامه وإنهاءه وإرسال تحديثه للمشرف. شاشة الموافقات التفصيلية لقبول/رفض تعديلات الفلوس أو الوزن أو العدد أو النوع تحتاج تحديث مستقل حتى تظهر كمراجعات قبل الاعتماد النهائي.
